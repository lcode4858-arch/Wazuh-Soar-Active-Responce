# Автоматизация защиты от брутфорс-атак с использованием Wazuh XDR (Active Response / SOAR)

## 📌 Описание проекта
В данном проекте реализован сценарий автоматического реагирования (SOAR) на распределенные атаки методом перебора паролей (брутфорс) на Windows-инфраструктуру. 
В качестве центрального элемента мониторинга и реагирования развернута SIEM/XDR система **Wazuh**. При фиксации критического всплеска неудачных попыток аутентификации (RDP/SMB), сервер Wazuh автоматически даёт команду агенту заблокировать IP-адрес атакующего на уровне встроенного сетевого экрана Windows.

## 🛠 Технологический стек
* **SIEM/XDR:** Wazuh Manager (All-in-One, v4.x)
* **Endpoint:** Windows 10 Enterprise LTSC (Wazuh Agent)
* **Attack Tool:** Hydra / Nmap (эмуляция нарушителя из смежного сегмента сети)
* **Протоколы защиты:** Windows Event Log (События аутентификации), Windows Defender Firewall

## 🚀 Пошаговая реализация

### Шаг 1. Подготовка инфраструктуры и аудит Windows
1. На целевой ОС Windows 10 настроена локальная политика безопасности (`secpol.msc`). Включен аудит отказов входа в систему (**Audit logon events -> Failure**). Это позволило ОС генерировать события Event ID `4625` в журнал безопасности.
2. Проверена сетевая связность и запущен мониторинг агента в панели Wazuh.

### Шаг 2. Эмуляция атаки (Брутфорс)
С хоста злоумышленника (Linux) была запущена атака на подбор учетных записей по протоколу SMB/RDP с помощью утилиты `hydra`:
\`\`\`bash
hydra -l administrator -P rockyou.txt smb://192.168.122.21
\`\`\`
*Здесь вставьте [Скриншот 1: Процесс атаки в терминале Linux]*

### Шаг 3. Настройка детекта и логики реагирования (Active Response)
На стороне Wazuh Manager в конфигурационный файл `/var/ossec/etc/ossec.conf` были внесены правила связи встроенного скрипта блокировки `netsh.exe` с алертами брутфорса (Правила `60122` и `60204`):

\`\`\`xml
<active-response>
  <command>netsh</command>
  <location>local</location>
  <rules_id>60122,60204</rules_id>
  <timeout>1800</timeout>
</active-response>
\`\`\`

   *Здесь вставьте [Скриншот 2: Дашборд Wazuh с резким пиком графиков]*
2. **Триггер защиты:** Сработал модуль Active Response, отправивший команду на изоляцию атакующего.
   *Здесь вставьте [Скриншот 3: Лог выполнения скрипта netsh из панели Wazuh]*
3. **Результат на эндпоинте:** На Windows 10 в Брандмауэре автоматически создалось блокирующее правило для IP нарушителя. Атака со стороны Linux полностью прекратилась по таймауту.

## 📈 Ценность для бизнеса (Бизнес-метрики)
* **Время реагирования (MTTR):** Снижено с условных 15-30 минут (время реакции дежурного аналитика SOC) до **3-5 секунд** (автоматическая блокировка).
* **Снижение рисков:** Полностью нивелирована угроза компрометации учетных записей сотрудников через подбор паролей на внешних или внутренних периметрах сети.
